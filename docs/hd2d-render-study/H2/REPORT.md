## 参数和操作

在庭院右下展开「景深」。开关、处理顺序和四个滑块均可实时更改，URL 保存设置。对照组统一使用光轴方向的对焦距离 27 m、焦平面锚点距画面顶部 50%、倾角 15°、最大模糊半径 12 CSS px。锚点指定穿过焦平面的屏幕高度；倾角为零时整个焦平面与成像平面平行，此时移动高度锚点自然不会改变结果。焦平面随相机移动。场景使用 H1-A 的入口机位，35° 俯角，方位角 28°，相机距离 27 m。

Native 景深从原尺寸的颜色与深度取样。前置景深从全分辨率场景取样，在像素网格中心计算模糊结果，再最近邻放大。这省去了对最终不会显示的中间像素做模糊。后置景深先按选定宽度生成颜色和深度，在全尺寸输出的每个像素上采样这张最近邻像素图。两种顺序共享同一深度权重、CSS 模糊半径与焦平面公式。全分辨率输入使用设备支持的最多 4 次 MSAA；像素输入沿用 H1-A 的单采样。顺序对照也包含这一输入采样差异。

## 视觉判断

- **小屋。** 27 m 处的门、窗框保留了清晰边界。屋顶跨越多个深度，靠后的瓦面有轻微软化。Native 原图适合检查门灯、藤叶与瓦垄细节。
- **前后景。** 离镜头近的右侧花墙和菜畦出现明显虚化，背景地面纹理变平缓。后排树冠与房屋部分处在相近深度，仍保有轮廓。调焦距离过短时小屋也会离开清晰带。
- **顺序。** 480 前置保留阶梯边缘；480 后置的前景过渡更连续，但一个显示像素格内部也会出现不同颜色。640 两种顺序的差异较小，适合检查瓦垄与植物细节。
- **边界。** 使用 32 点屏幕空间采样，按线性深度差抑制跨轮廓串色。细藤、立柱及树叶交叠处可能残留硬边；单层深度无法恢复被前景遮挡的颜色。颜色在沿用 H1 输出的显示空间混合，高亮散景与真实镜头仍有差距。此轮以静态外观与交互复现为验收依据。

## 验证

Chrome 157，视口 1440×960、DPR 1，画布 1440×826，480 和 640 对应 480×275、640×367。八张图逐张断言相机世界矩阵一致，三张关闭景深的 PNG 与 H1-A 已提交的入口 PNG 字节一致。每组预热 30 帧并采 60 个浏览器帧间隔，均值约 16.7 ms。该结果受刷新率影响，未测 GPU 耗时。Native 关闭/开启分别为 10/11 次绘制；Pixel 关闭、前置、后置分别为 11、12、11 次，后置在最终呈现时同时完成模糊。

运行 npm run lint、npm run typecheck、npm test、npm run build 及 npm run test:browser。H2 测试覆盖八组截图、实际图像差异、无 WebGL 错误、滑块交互、调整后刷新复现、缩放与视口调整。按 captures.json 中的查询参数可重现每张图。合图由同目录 contact_sheet.py 使用 Pillow 从原始 PNG 制作。Vite 主包体积提示仍在。视觉结论待人工确认。

最终生产构建验证通过：lint、TypeScript strict、24 项单元测试及 15 项 Playwright 浏览器测试全部通过。
