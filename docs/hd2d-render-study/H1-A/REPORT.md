## 渲染与复现

入口为 `/?scene=courtyard`。以 `/?scene=courtyard&render=pixel&pixelWidth=480` 直接打开实验档位。底部选择器支持原地切换，保持相机姿态并更新 URL。画布不缩放，内部目标按绘图缓冲区比例取整，限制在设备和缓冲区范围内。Pixel 以最近邻取样铺满画布。在 1440 宽度下，640 和 320 分别放大 2.25 和 4.5 倍，部分像素列宽相差一个屏幕像素。精细几何在移动时可能跨越采样点，静态截图和交互冒烟测试不足以评定动态闪烁程度。

Pixel 使用 Three r186 的屏幕输出目标标记，在 RGBA8 目标上复用 Native 的色调映射、sRGB 和雾色混合顺序，再直接复制显示颜色。该标记依赖 Three 版本，升级时应重新对照。入口 Native 图与分支基线庭院入口图逐像素一致。三档 Pixel 入口全图平均 RGB 每通道与 Native 的差均小于 0.11（8 位刻度）；局部仍有预期的采样差异。

## 截图与性能

Windows，本机 Chrome 157.0.8103.52，Playwright headless，CSS 视口 1440×960，DPR 1，画布 1440×826。两机位均为 35° 俯角、35° 垂直视场、距离 27 m，观察点 (0, 1.15, 0.1)。入口方位角 28°，侧面通过水平拖动 160 CSS 像素得到方位角约 −0.8°。每个机位内四档相机世界矩阵逐元素差小于 0.00001。截图只隐藏覆盖在画布上的文字和控件。

每机位依次运行 Native、640、480、320。每档预热 90 帧，通过 requestAnimationFrame 连续采样 120 个间隔。入口与侧面共八组均约 **16.67 ms/帧、60.0 FPS、P95 16.8 ms**。这是单机短时浏览器帧间隔，受到显示刷新节奏限制，无法据此判定 GPU 节省量。每帧 Native 计 10 次绘制、377840 个三角形；Pixel 三档均计 11 次绘制、377841 个三角形。计数包含阴影和最近邻呈现用的全屏三角形。
