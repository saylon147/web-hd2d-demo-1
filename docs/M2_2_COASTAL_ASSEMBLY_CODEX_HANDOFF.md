# M2.2 — Tripo A1–A4 海岸模块拼装实验（Codex Handoff）

> 状态：实施计划，**非最终美术批准**。基线：`codex/tripo-rock-pipeline-spike`。不要直接改动 M2.1 岛屿/房屋/地下室的原始生成逻辑。建议从本分支再建独立实施分支 `codex/m2-2-coastal-assembly`。

## 目标和边界

利用用户在 Tripo 生成并本地提供的四种海岸模块 A1–A4，验证 **批量 GLB 优化 → 尺度标定 → 局部海岸拼装 → Golden Reference V1 同机位视觉对照**。第一轮只覆盖主视角可见的海岸约 1/4，尤其是码头侧或前侧；不重做整座岛、不修改精确建筑结构、不承诺最终美术。此前单图岩石仅作为对照，不算 A1–A4 之一。

## 用户交付的输入文件（本地，不提交 Git）

将以下文件放到仓库工作树的 `art-source/tripo/inbox/`，大小写、下划线按约定：

| ID | 文件 | 用途 |
|---|---|---|
| A1 | `coastal_cliff_A1_multiview.glb` | 高耸的垂直悬崖 |
| A2 | `coastal_cliff_A2_multiview.glb` | 宽而低的横向岩壁 |
| A3 | `coastal_corner_A3_multiview.glb` | 非对称海岸转角 |
| A4 | `coastal_platform_A4_multiview.glb` | 顶部相对平缓的台地边缘 |

原始文件不入 Git；确保 `.gitignore` 覆盖 `art-source/tripo/inbox/*.glb` 和所有生成的大体积 GLB。若 A3/A4 尚未下载，**先完成已有资产的检测与预览**，报告缺失资产，不得伪造占位为已交付、也不得悄悄生成替代 GLB。待齐备再执行完整拼装验收。原始文件只读，不覆盖。

## Phase 0：基线检查与资产审计

1. 读取 `docs/TRIPO_ASSET_PIPELINE.md`、`docs/tripo-rock-spike/RESULTS.md`、现有 pipeline 脚本及 M2.1 场景配置；检查实际相机、岛屿轮廓、房屋/地下室、码头位置，**从代码提取世界尺度**，不把此前讨论的估算米数当作真实场景参数。
2. 对四个输入分别记录 SHA-256、大小、三角形数、mesh/material/texture 数、PBR 通道、bounding box、坐标轴、UV、是否封闭、非流形/异常几何。多 mesh、多材质或非标准扩展应显式处理或给出清楚的错误，不能默认四个输入与第一块岩石结构完全一致。
3. 保留每个资产原始正面/左右/背面/顶部截图，特别检查多视图模型侧背差异。保存本地 manifest 和审计报告。

## Phase 1：通用批处理和尺寸规范化

1. 将单岩石 spike 管线扩展为可配置的多资产批处理；每个资产独立参数，保留源模型、源贴图和中间产物，处理可重复、支持失败后单项重跑。
2. 每个资产至少导出 `10k/1K` 和 `20k/2K` 两档候选；必要时增加 `5k/1K`、`50k/2K`，但不强制所有模型使用同一档。保留颜色、法线和粗糙度/金属度通道；记录纹理压缩、mipmap 与 Web 解码开销。**不得假定法线重烘焙已经完成**。
3. 按真实世界参数对齐 Y-up、地面锚点、单位尺度；每个资产的推荐目标尺寸、允许缩放范围、可见面方向、嵌入深度放到独立 JSON 配置。允许适度非等比缩放，但检查岩石纹理/法线是否被明显拉伸；不得把精确碰撞/地形逻辑交给不规则 Tripo 网格。
4. 输出 `asset-manifest.json`：资产 ID、来源、原始哈希、优化版本、三角形、GLB 大小、纹理分辨率、世界尺度、推荐用途、限制和状态。

## Phase 2：可切换的海岸拼装实验

1. 在现有 Three.js 诊断界面增加独立 `coastal-assembly` 实验场景或开关，默认不影响 M2.1 基线。原始程序化岛屿、房屋、地下室、台地、码头的结构和坐标保持不变。
2. 用 A1（高度）、A2（横向）、A3（转角）、A4（顶面过渡）组合主视角可见海岸约 1/4。允许同一模块多次复用（旋转、镜像需检查法线、缩放、局部嵌入），但避免明显重复花纹、悬空、交叠穿帮和人工砌墙感。先做有依据的 placement JSON，再通过代码加载；不要将摆放坐标散落在渲染逻辑中。
3. 岛屿的**可行走表面、房屋地基、地下室入口、楼梯/碰撞仍使用原始程序化几何**。Tripo 仅为可见岩壁和局部边缘装饰。处理岩壁与原地形接缝、色温/粗糙度/光照一致性；不能只靠大块岩石遮挡所有问题。
4. 提供 A/B 切换：M2.1 原始海岸、Tripo 拼装海岸、单模块检查。支持全景及前/侧/背/顶视角，并显示资产 ID、世界尺寸、LOD 和开关。移动宽度不允许控件重叠。

## Phase 3：验收和报告

- **视觉**：Golden Reference V1 主视角同相机/光照对比，另给近景、转角、背面、顶部截图；重点审视岩壁是否自然衔接、是否仍有规则台阶/砌墙感，以及 A1–A4 的风格/色彩是否统一。
- **技术**：每个输入及优化版本校验 GLB 可加载、材质纹理、UV、轴向、锚点、尺寸、非空几何；检查纹理缩放/法线一致性。记录每种配置的模型数、draw calls、triangles、纹理内存估算、GLB 体积、加载时长、FPS/帧时长。区分桌面与模拟移动视口，不得把模拟视口称为真机测试。
- **回归**：原 M2.1 基线场景可访问、房屋和地下室参数未改动，现有 lint/typecheck/unit/browser/build 测试通过；为拼装开关、缺文件提示、资产清单及移动布局增加测试。
- **交付**：可重复的一键命令、配置和代码；`docs/m2.2-coastal-assembly/RESULTS.md`、截图、manifest、测试记录；列出未解决问题及后续需要新增的资产类型。**不自动合并分支**，先让用户审图决定是否继续。
- **停止条件**：缺失 GLB、材质失真、岩壁衔接明显穿帮、基线破坏、浏览器性能/内存显著恶化时先报告，不强行宣称完成。

## 建议执行顺序

审计已有 A1/A2 → 等待 A3/A4 → 四资产批量优化 → 布置 JSON → 局部拼装 → 同机位截图与性能/回归 → 用户审查。当前第一块单图岩石管线的结论是技术可行，不代表所有新资产都已经通过质量验收。
